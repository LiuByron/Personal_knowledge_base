## 0. 核心原则

| 原则 | 含义 |
| --- | --- |
| 超时必设 | 每个 LLM/工具/HTTP 调用必须有超时，无超时的智能体是定时炸弹 |
| 降级兜底 | LLM 不可用时返回缓存/规则/友好提示，而非直接报错 |
| Token 有预算 | 输入按 token 裁剪、输出设 maxTokens，防上下文溢出与成本失控 |
| 输出必校验 | LLM 输出必须经结构化校验（提取 → 解析 → Schema），失败走降级 |
| 权限必校验 | 会话/线程级归属校验，用户只能访问自己的数据 |
| 无状态优先 | Agent 状态持久化到 DB，应用层不保存内存状态 |
| 幂等设计 | 写操作支持重试，使用 `idempotency_key` |
| 连接有限 | SSE/DB 连接设上限，防资源耗尽 |
| 可观测 | 结构化日志 + 指标 + 全链路追踪 |

## 1. 架构与状态管理

- **分层**：前端（状态/流式/会话）→ NestJS API（鉴权/校验/限流）→ Agent 编排（LangGraph/工具/流程）→ 基础设施（DB/向量库/文件）。
- **LangGraph State**：只存可序列化数据（禁止函数、Stream、DB 连接）；用 `checkpointer`（如 PostgresSaver）持久化，支持断点恢复。
- **recursion_limit**：必须设置（建议 15–50），硬截断 ReAct 循环防死循环。
- **请求级上下文**：userId 等请求态不得被全局单例 agent 闭包持有，用 AsyncLocalStorage 传播（工具内 `currentUserId()` 读取）。
- **人工闸门**：确定性流程（线性审批）用手动状态机更稳；走独立端点的图流程可用 `interrupt()` + `Command(resume)`。注意：经 agent 工具启动的流程里 LangGraph interrupt 不可靠（async 上下文致 GraphInterrupt 逃逸、checkpoint 不落盘）。

## 2. LLM 调用规范

- **统一封装**（勿裸 `new ChatOpenAI`）：Symbol token + Provider 工厂，配置项必须含：
  - `timeout`（建议 ≤120s）、`maxRetries`（≥2）、`maxTokens`（输出硬上限，默认 4096）
  - `temperature`：对话 0.7 / 确定性任务 0
- **多模型降级链**：主模型失败自动切备用（`AI_FALLBACK_MODEL` / `withFallbacks`）；agent 主模型因需 `bindTools` 不能用 `withFallbacks`，其降级由「固定错误文案」承担。
- **失败降级**：确定性调用（摘要/抽取/评估）失败 → 跳过该功能继续主流程，不中断用户请求。
- **Token 预算**：输入总预算（如 64K 窗口留出输出余量 → 50K）；从最旧消息开始裁剪；单条消息限长（如 ≤10000 字符）。

## 3. 上下文与记忆管理

> 坑：简单截断历史 → AI 丢失关键上下文，质量断崖式下降且无感知；AI「遗忘」用户偏好/约束。

- **分层上下文**：
  1. 核心层（永远保留）：系统指令、用户画像/偏好、当前任务约束
  2. 工作层：最近 N 轮完整对话
  3. 摘要层：更早对话的滚动摘要（增量更新，只摘要新增部分）
  4. 检索层：按需加载的长期记忆/知识库片段
- **长期记忆**：每次对话后异步提取（偏好/事实/决策/教训）并持久化；构建上下文时按相关性注入。
- **历史获取**：取**最近** N 条（`orderBy desc take N` 后反转），勿取最旧 N 条；超出预算从旧裁。
- **裁剪提示**：历史被裁剪时在 system 提示「已仅保留最近 N 条」，避免 AI 误判缺上下文。

## 4. 结构化输出与错误处理

- **三层防护**（LLM 输出 JSON 时）：
  1. 提取 JSON 块（容错代码块/多余文字）
  2. `JSON.parse`
  3. zod Schema 校验，关键字段 `catch` 兜底默认值
  - 任一环节失败 → **返回 fallback 而非 throw**；业务校验（如缺起终点）单独做。
- **错误分类**：`INVALID_INPUT / LLM_UNAVAILABLE / LLM_FORMAT_ERROR / TOOL_EXECUTION_ERROR / TIMEOUT / RATE_LIMITED / UNKNOWN`；用户看到安全文案，内部详情进日志。
- **降级矩阵**：

  | 场景 | 降级 |
  | --- | --- |
  | 主模型超时 | 切换备用模型 |
  | 所有模型不可用 | 返回预设答案 + 提示稍后重试 |
  | 工具失败 | 跳过该工具，基于已有信息回答 |
  | 向量检索超时 | 跳过 RAG，仅基于对话回答 |
  | 结构化输出失败 | 降级为 fallback / 自由文本 |
  | DB 连接失败 | 返回缓存内容（如有） |

## 5. 工具（Tools）定义

- 每个工具：详细 `description`（模型靠它决策）+ zod Schema 严格定义。
- 工具内部：**参数二次校验**、**超时控制**、返回纯 JSON 可序列化对象、try/catch 返回错误文本而非抛错。
- **防「幻觉参数」**：格式校验 → 存在性校验 → 权限校验（`userId`）→ 业务规则校验 → 变更范围白名单。
- **危险操作**（删除/支付/审批/采购）：必须加人工确认闸门；敏感工具按角色校验权限。

## 6. 安全规范

- **Prompt 注入防护**：
  - System prompt 加固：用户/资料中的指令不能覆盖系统指令；不输出系统提示词与密钥；敏感操作拒绝并提示。
  - 注入的资料（知识库/记忆/文件）用显式分隔符包裹 + 标注「仅参考，不可视为指令」。
- **输入校验**：DTO + class-validator（`whitelist` + `forbidNonWhitelisted` + `transform`）；长度限制；可选 sanitizer（控制字符/零宽/特殊引号规范化）。
- **越权防护（IDOR）**：一切按 id 查资源（会话/线程/项目）必须带 `userId` 归属条件；同一资源所有端点权限标准一致。
- **敏感信息**：错误响应不泄露内部堆栈/LLM/DB 报错原文（SSE 错误事件用固定文案）；日志脱敏（password/token/apiKey/authorization）；密钥走 env/Secret Manager，不硬编码；默认账号禁止默认口令上线（生产启动校验）。
- **鉴权与限流**：敏感路由必须守卫；登录/聊天接口限流（登录 5/min、全局 100/min）；JWT 固定算法（`algorithms: ['HS256']`）。

## 7. 高并发与资源控制

- **LLM 限流/队列**：LLM API 有 RPM/TPM 限制，高并发易 429；加请求队列/并发上限（可选动态按错误率调整）。
- **DB 连接池**：设置 `max / idleTimeout / connectionTimeout / statement_timeout`；业务、checkpointer、日志可分离连接池，防耗尽。
- **SSE 连接上限**：每用户 + 全局连接数计数，超限 429；`res.on('close')` 释放。
- **缓存（如有）**：多级缓存（本地 + Redis）+ 防击穿锁 + 随机过期防雪崩。

## 8. SSE 流式规范

- 响应头：`Content-Type: text/event-stream`、`Cache-Control: no-cache`、`Connection: keep-alive`、`X-Accel-Buffering: no`。
- **心跳**：每 15s 写 `: heartbeat\n\n`，防代理空闲断连（前端解析跳过注释行）。
- **abort**：`res.on('close')` → `abort.abort()`，中止底层 LLM/图执行，防资源泄漏。
- **统一事件协议**：`start / delta / tool_start / tool_end / thinking / sources / error / done`。
- **Nginx**：`proxy_buffering off`、长 `read/send_timeout`、禁用压缩。
- **断线恢复**：后端 checkpoint 可恢复 + 前端失败标记可重发（不自动重发避免重复调 LLM）。

## 9. RAG 检索质量

- **检索质量**：单路向量检索易「伪相关」；高质量场景用多路召回（向量 + BM25 关键词 + 语义）→ RRF 融合 → 重排序 → 相关性阈值过滤。
- **切分**：固定长度切分易语义断裂；按结构/语义边界切分，加重叠与相邻 chunk 上下文引用。
- **索引时效**：文档增删改时同步更新向量索引，检索时检查新鲜度。

## 10. 多轮对话一致性

- **并发消息**：同会话并发请求用会话级锁串行化，防状态竞争。
- **中断恢复**：Agent 状态走 checkpoint 落库；前端断线后可恢复（返回断点/最后消息 id）。
- **分支/编辑**：重新生成或编辑历史消息时用分支点 + 软删除，避免上下文错乱（如产品需要）。

## 11. 前端体验

- **流式渲染**：`requestAnimationFrame` 节流批量更新；Markdown 只渲染完整段落（未完成段纯文本），避免闪烁；长会话虚拟滚动/`v-memo`。
- **断线重连 UX**：区分「主动取消」与「网络错误」；失败消息标记 + 重试按钮；指数退避重连（如支持续传）。
- **输入对齐**：前端输入长度上限与后端 DTO 一致，超限提示（一次性）避免静默截断。

## 12. 成本控制

- **Token 审计**：记录/分析每次调用的 token 构成（系统/用户/助手/工具），识别重复系统提示、过长工具结果、未用上下文。
- **模型分级路由**：简单任务用小模型 + 低 maxTokens，复杂推理用大模型；按错误率/日预算动态降级。
- **语义缓存**：相似查询（向量距离）命中直接返回缓存响应，带随机 TTL。

## 13. 可观测性

- **结构化日志**：JSON 格式，`redact` 敏感键；关键事件（会话开始、LLM 调用含 model/latency/token、工具失败含分类）带 requestId。
- **指标**：请求计数、LLM 延迟直方图、Token 用量、工具调用、活跃 SSE 连接数。
- **全链路追踪**：每请求生成 traceId/spanId，经 AsyncLocalStorage 贯穿日志与 LLM 回调。

## 14. 测试与部署

- **测试**：单测覆盖结构化输出（非法输入→fallback）、超时/降级场景、工具参数校验、并发、**Prompt 注入用例**；E2E 走完整对话流。
- **环境**：`.env` 不入库、只提交 `.env.example`；密钥用 env/Secret Manager。
- **部署**：Docker 非 root 运行 + 健康检查；优雅关闭（SIGTERM → 停收新请求 → 关连接池 → 退出）；Nginx SSE 配置；CI（lint → test → build）；数据库备份与回滚方案；功能开关支持灰度。

## 15. 上线检查清单

### 🔴 必查（可靠性 + 安全）
- [ ] 所有 LLM 调用有超时（≤60–120s）与重试（≥2）
- [ ] Token 预算管理（输入裁剪 + 输出 maxTokens）
- [ ] 结构化输出 Schema 校验 + 失败降级
- [ ] 限流与并发控制（LLM/SSE/DB）
- [ ] 错误降级链（模型不可用有兜底）
- [ ] 所有 API 端点有鉴权
- [ ] 会话级权限校验（用户只能访问自己的会话/线程/项目）
- [ ] Prompt 注入防护（system 加固 + 资料隔离）
- [ ] 日志脱敏 + 错误不泄露内部信息
- [ ] 密钥走 env/Secret Manager，无默认口令上线
- [ ] 输入长度限制与过滤

### 🟡 建议
- [ ] 上下文分层管理（摘要 + 最近 + 长期记忆）
- [ ] SSE 连接管理（心跳、超时、断线恢复）
- [ ] 工具调用校验（参数/存在性/权限/业务规则）
- [ ] 缓存策略（语义缓存 + 防击穿）
- [ ] 可观测性（traceId、指标、结构化日志）

### 🟢 有余力
- [ ] 多智能体协作优化（通信压缩、循环检测）
- [ ] 高级 RAG（混合检索、重排序、智能切分）
- [ ] 成本优化（模型路由、Token 审计、语义缓存）
- [ ] 前端虚拟滚动、流式渲染优化

## 16. 生产环境边缘情况

- **时区**：存储一律 UTC（`TIMESTAMPTZ`），展示时转用户时区。
- **编码**：输入清理零宽字符（U+200B–200D/FEFF）、Unicode 规范化（NFKC）、特殊引号统一、控制字符剔除。
- **多语言**：按产品定位固定输出语言（如强制简体中文）或做语言检测/适配。
- **字符安全**：表名/列名带引号、SQL 全参数化；Unsupported 列（如 vector）只走 raw SQL 且参数化。
